# 项目存在问题（按修复难度分级）

## 1. 说明
- 本文档基于当前仓库代码、配置与可执行检查结果整理，聚焦“会影响真实功能可用性”的问题。
- 分级维度：同时考虑修复难度与业务影响，优先处理“低成本高收益”项。
- 分级定义：
  - **S级（优先修复）**：修复成本低、影响面大、可快速提升可用性。
  - **A级（近期修复）**：修复成本中等，涉及模块联动或配置重构。
  - **B级（中期优化）**：修复成本较高，偏工程治理与体系化能力建设。

## 2. 检查基线
- 后端语法编译：`python -m compileall backend` 通过。
- 前端构建：`npm run build` 通过，但存在大体积 chunk 告警。
- 后端自动化测试：当前环境缺少 `pytest`，无法执行 `python -m pytest backend/tests -q`。

## 3. S级（低难度 / 高收益）

### S-01 Docker Compose 前端镜像无法构建
- 现象：`docker-compose.yml` 指向 `frontend/Dockerfile`，仓库中不存在该文件。
- 影响：`docker compose up -d` 无法完整拉起，前端服务不可用。
- 建议修复：
  1. 补齐 `frontend/Dockerfile`；或
  2. 调整 compose 为已有构建方式（如改为静态资源 + Nginx 镜像）。

### S-02 Prometheus 启动配置缺失
- 现象：compose 挂载 `./deploy/prometheus.yml`，实际缺失。
- 影响：监控容器启动失败，指标观测能力不可用。
- 建议修复：
  1. 新增 `deploy/prometheus.yml`；
  2. 在 compose 中增加文件存在性检查说明。

### S-03 CI 流水线引用不存在目录
- 现象：GitHub Actions 中存在 `cd java_processor`，仓库无该模块。
- 影响：CI 固定失败，影响集成验证与发布门禁。
- 建议修复：
  1. 删除该阶段；或
  2. 以条件判断执行该步骤（模块存在才运行）。

### S-04 Jenkins 集成测试依赖缺失文件
- 现象：Jenkinsfile 运行 `newman` 时引用 `postman_collection.json` 与 `postman_environment.json`，仓库缺失。
- 影响：集成测试阶段失败，导致流水线不稳定。
- 建议修复：
  1. 补齐 Postman 文件；
  2. 若暂不启用，改为可选阶段并在日志中明确跳过原因。

### S-05 接口在空 JSON 请求下会触发 500
- 现象：`/api/ai/execute_command` 与 `/api/auth/refresh` 对 `request.get_json()` 结果未做空值保护，直接 `.get(...)`。
- 影响：客户端请求体异常时返回 500，而不是可恢复的 4xx。
- 建议修复：
  1. 统一判空：`data = request.get_json(silent=True) or {}`；
  2. 缺参返回标准化错误码与提示。

### S-06 服务启停布尔参数解析错误
- 现象：`enabled = bool(payload.get("enabled", True))`，当传入 `"false"` 字符串时仍为 `True`。
- 影响：本应禁用的请求可能误执行“启用”，产生业务语义错误。
- 建议修复：
  1. 实现严格布尔解析（仅接受 true/false 布尔或明确字符串映射）；
  2. 非法值直接返回 400。

## 4. A级（中难度 / 中高收益）

### A-01 Redis 配置加载时序不安全
- 现象：`app.py` 在加载本地环境变量前导入 `redis_client`，后者导入时即实例化连接参数。
- 影响：仅依赖 `.env` 时可能连到错误 Redis 地址/端口，表现为功能随机异常。
- 建议修复：
  1. 调整初始化顺序（先加载配置，再实例化客户端）；
  2. 或改为惰性初始化（首次使用时读取配置）。

### A-02 Celery Redis 连接串未覆盖密码与 DB
- 现象：`tasks.py` 仅使用 host/port 组装 broker/backend URL，忽略密码与 DB。
- 影响：启用 Redis 鉴权或多 DB 隔离时，异步任务不可用。
- 建议修复：
  1. 使用完整 URI 组装逻辑；
  2. 与主应用 Redis 配置保持同源。

### A-03 前端“服务器管理”页面路由不可达
- 现象：存在 `Servers.vue`，但路由表未注册 `/servers`。
- 影响：页面功能悬空，用户无法从界面进入对应能力。
- 建议修复：
  1. 补齐路由与菜单入口；或
  2. 若已废弃则删除页面并清理相关引用。

### A-04 同一能力权限语义不一致
- 现象：部分页面提示“仅管理员可新增服务器”，但其他页面可触发新增入口；后端又允许 `operator` 执行新增。
- 影响：前后端权限认知不一致，易产生越权争议与操作混乱。
- 建议修复：
  1. 统一权限模型（文案、前端控制、后端鉴权一致）；
  2. 输出角色-能力矩阵并做回归测试。

### A-05 跨环境端口约定不统一
- 现象：本地开发默认 5001，容器化后端为 5000。
- 影响：环境切换时前端代理或联调容易“页面可开但 API 不通”。
- 建议修复：
  1. 统一端口策略；
  2. 明确区分 dev/prod 配置并在文档给出映射表。

## 5. B级（高难度 / 治理型收益）

### B-01 关键链路吞异常导致“静默失败”
- 现象：数据接入与自动采集逻辑中存在 `except: pass` / 无告警处理。
- 影响：故障发生时接口可能仍返回成功或无明显报错，导致问题难定位。
- 建议修复：
  1. 建立统一错误处理与日志规范；
  2. 对采集、写入失败增加告警和指标埋点；
  3. 引入失败重试与熔断策略。

### B-02 配置安全治理未完全工程化
- 现象：存在开发默认密钥回退，且仓库中包含敏感配置样例。
- 影响：生产配置失误时风险放大，且影响团队安全基线。
- 建议修复：
  1. 生产环境强制关键密钥必填；
  2. 建立配置扫描与提交前校验；
  3. 区分示例配置与真实配置载体。

### B-03 前端构建产物体积偏大
- 现象：`npm run build` 出现多个大 chunk 告警（>500KB）。
- 影响：首屏加载与弱网体验下降，间接影响功能可用性感知。
- 建议修复：
  1. 按路由与模块做动态拆包；
  2. 对可选功能库做懒加载；
  3. 建立构建体积基线阈值。

## 6. 真实环境联调发现并已修复的缺陷（2026-11）

以下问题在「本机 MySQL + Redis + SSH 连接 Ubuntu 虚拟机」的真实联调中暴露，
均已修复并补充回归测试。修复分支 `fix/pre-test-hardening`。

### F-01 智能助手链路完全没有审计（安全缺陷）
- 现象：`routes/assistant.py` 从未调用 `write_audit_log`，`audit_logs` 表在生产环境恒为空。
- 影响：助手方案的生成、拦截、执行全部无记录，审计闭环在最关键的链路断裂。
- 修复：补齐 4 个写入点 —— 高危拦截（`result=blocked`）、方案生成（`planned`）、
  执行成功/失败（`action=assistant_execute`）、执行异常（`error`）；
  并在 pending token 中保存 `command_raw` 保留用户原始输入。
- 回归：`tests/test_assistant_ops.py::TestAssistantAudit`

### F-02 智能助手执行链风险拦截缺失（P0 安全漏洞）
- 现象：`ops-plan` 对 `evaluate_risk` 判定 `allowed=False` 的命令仍签发 `execution_token`，
  用户确认二次弹窗后高危命令会被 `run_command_stream` 真实下发。
- 影响：这是前端唯一在用的执行链路，风险拦截形同虚设，可执行 `rm -rf` 等破坏性命令。
- 修复：`ops-plan` 风险不允许时直接 403 且不签发令牌；`ops-execute` 执行前按当前
  请求角色重新评估，防止令牌签发后以更低权限重放。
- 回归：`tests/test_assistant_ops.py::TestOpsPlanRiskGate` / `TestOpsExecuteRiskGate`

### F-03 `run_command_stream` 默认分配 pty 导致服务操作卡死
- 现象：`get_pty=True` 时 `systemctl restart xxx` 不会关闭通道，读取循环跑到 timeout。
- 实测：同一台机器 `systemctl restart syslog`
  - `get_pty=True` → 12.1s 超时未返回
  - `get_pty=False` → 0.0s 立即返回
- 影响：`/api/services/control` 稳定返回 500，服务启停完全不可用。
- 修复：改为 `use_pty` 参数、默认 `False`，仅交互式场景显式开启。
  修复后同一请求 2.4s 返回准确的 403 权限错误。
- 回归：`tests/test_ssh_pty.py`

### F-04 MFA 短码永远校验失败（功能完全不可用）
- 现象：`expires_at` 用 `datetime.utcnow()` 写入，校验语句为 `expires_at > NOW()`。
- 实测：同一时刻 `expires_at=13:33:22`(UTC)、`NOW()=21:28:47`(本地)，相差 8 小时，
  写入即过期。
- 影响：所有高危命令的 MFA 短码确认 100% 失败。
- 修复：`ws_terminal.py` 与 `auth.py` 的 MFA 签发改用 `datetime.now()`。
  （JWT 的 `exp` 与内存内 `last_activity` 均以 UTC 自洽，保持不变。）
- 回归：`tests/test_mfa_timezone.py`

### F-05 服务控制回退成功却返回错误信息
- 现象：`_try_commands` 在 `sudo` 回退成功后，仍把前序命令的 stderr 写进结果。
- 影响：接口返回 `{"ok": true, "message": "ok", "stderr": "Interactive authentication required"}`，
  前端依据 message 显示为失败，用户误判。
- 修复：成功时直接返回该次执行的真实输出，不合并前序回退产生的错误。
- 回归：`tests/test_service_manager.py`

### F-06 `deploy/init.sql` 不可重复执行
- 现象：新建库时 `user`/`servers` 的 `tenant_id` 已在 `CREATE TABLE` 定义，
  后续 `ALTER TABLE` 再添加报 `ERROR 1060 Duplicate column name`，导致建库中断。
- 影响：二次执行 `mysql < init.sql` 失败；已有库升级与全新部署路径不一致。
- 修复：改为 `information_schema` 判存在 + `PREPARE` 动态执行的幂等写法。
  已验证连续导入两次均无错误。

### F-07 风险分级阈值与打分口径不一致
- 现象：管道与重定向各 +10 分，但 MEDIUM 阈值设为 `>= 40`。
- 影响：`cat /etc/passwd > /tmp/out`（得分 20）被判为 LOW，operator 直接放行，
  敏感文件可被导出到 /tmp。
- 修复：阈值调整为 `>= 10` 即 MEDIUM，与打分口径对齐。
- 回归：`tests/test_command_risk.py`
